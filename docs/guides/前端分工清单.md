**合并顺序（合进 `main`）：** B → C → D → E → F → G → H → I → J  

**共用约定**

- 页面只调 `frontend/src/api/*.ts`，不写裸 axios URL
- 不删他人路由与 nav 项；新入口仅 **追加**
- `layouts/`、`components/ui/` 仅 B 或 A 修改
- 预览路由 `/preview/**` 与正式路由共用同一 View 组件
- 命名遵循 `docs/文件命名规范.md` 第三节（页面 `{Feature}View.vue`，API 小写复数）
- **登录改造（仅 B 改）：** `LoginView.vue`、`api/auth.ts` 从 `identifier + phoneNumber` 改为 `loginName + password`；合并前 **C～J 勿改** 上述文件。B 未合并前可用 `/preview/**` 看骨架，或暂用旧登录联调
- **登录会话不变：** `LoginResult.userId` 仍为业务 ID（`member_id` / `emp_id` / `coach_id`），各模块继续用 `authStore.session?.userId`，**D～J 业务页无需改**

**本地启动**

```powershell
# 后端（项目根目录）
dotnet run --project backend/Api/Api.csproj

# 前端
cd frontend
npm install
npm run dev
```

登录页：`http://localhost:5173/login`。会员预览档案侧栏使用演示 ID `1`（`config/nav.ts` 中 `PREVIEW_MEMBER_ID`）。

**占位页：** 侧栏点进未实现模块时，显示「站点骨架 · 占位页」；`routes.ts` 的 meta 标注负责人与功能点 #。替换时在 `routes.ts` 只改 `component`，**path 不变**。

## 六、替换占位页步骤

```text
1. git pull origin main && git checkout -b feature/你的模块
2. 对照第四节确认路由与功能点
3. 后端 Controller 先在 http://localhost:5078/api/... 通 JSON
4. 新建 frontend/src/api/xxx.ts
5. 新建 views/.../XxxView.vue（命名见文件命名规范）
6. router/routes.ts：仅改对应 path 的 component
7. npm run build 通过 → PR（写清页面 URL、功能点 #、依赖 API）
8. A 按 B→…→J 顺序合并；冲突文件：routes.ts、nav.ts、DI
```
