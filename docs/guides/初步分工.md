# TJ-GYM 十人分工

成员以 **A～J** 代替姓名，组内填真实姓名即可。  
每人负责一个业务模块的 **全栈实现**（C# 五层 + Vue 页面 + Oracle 对象），对应需求用例包 §2.2～§2.9。

| 代号 | 角色 | Git 分支 | 职责 |

| **B** | 样板负责人 | `feature/member-template` | 维护会员登录/档案/编辑样板，作为全组复制标准；第一个合并进 `main` |

**A — 集成负责人**

- 保护 `main`，业务代码仅通过 PR 合并
- 每天合并不超过 1～2 个 PR
- 合并顺序：B → C → D → E → F → G → H → I → J
- 各 PR 若未改共享文件，按 PR 描述为作者追加 DI / 路由注册
- 确保密码不进入 Git；推动云部署与答辩前集成验收

**B — 样板负责人**

- 完善会员模块：登录、档案查询、个人信息编辑
- 对照 `MembersController` / `MemberRepository` / `LoginView` 整理组内复制要点
- 可选：补 1 个会员相关 Oracle 函数
- 尽早 PR 合并进 `main`，通知全员 `git pull origin main`

**C～J — 模块开发**

每人独立完成本模块：

```text
Repository → DTO → AppService → Controller → api/*.ts → View
+ database/oracle/ 下至少 1 个 .sql，并在 Oracle 库中执行验证
```

- 从 `main` 拉分支，禁止直接在 `main` 开发
- 至少交付 **2～3 个用例**、**1 个可演示页面**、**1 个查库 API**
- 合并前：`dotnet build` + `npm run build` 通过

## 三、Oracle 对象分工

### 课程要求

视图、存储过程、函数、触发器 **必须在 Oracle 数据库里创建**，不能只在 C# 里写等价逻辑。全组合计四类至少各 1 个。

### 脚本放在哪

```text
database/oracle/
├── views/
├── procedures/
├── functions/
└── triggers/
```

仓库里已为 D、E、F、J 放了 **4 个示例脚本**（可按实际表结构修改）。C、G、H、I 在对应子目录 **新建** 自己的 `.sql`，只增不盖他人文件。

| 代号 | 类型 | 脚本文件名 |
| --- | --- | --- |
| C | 视图 | 自建，如 `v_venue_equipment_summary.sql` |
| D | 函数 | `fn_is_card_valid.sql` |
| E | 触发器 | `trg_checkin_update_venue.sql` |
| F | 存储过程 | `sp_book_group_course.sql` |
| G | 存储过程 | 自建 |
| H | 函数 | 自建 |
| I | 触发器 | 自建 |
| J | 视图 | `v_member_booking_summary.sql` |

### 怎么执行

1. SQL Developer 或 DBeaver 连接组内共用 Oracle。
2. 打开 `database/oracle/` 下自己的 `.sql`。
3. **F5 Run Script** 执行整份脚本。
4. 在 SQL 窗口验证，例如：

```sql
-- 视图
SELECT * FROM v_member_booking_summary WHERE ROWNUM <= 10;

-- 函数
SELECT fn_is_card_valid(1) AS is_valid FROM DUAL;

-- 触发器：插入 CHECKINOUT 后查 VENUE.CURRENT_CAPACITY 是否变化

-- 存储过程
VAR result NUMBER;
VAR message VARCHAR2(200);
EXEC sp_book_group_course(1, 1, 90001, :result, :message);
PRINT result;
PRINT message;
```

5. 验证通过后 `git add` 该脚本并 commit。

### 和 C# 的关系

简单单表查询用 EF（Repository）。多表事务、自动联动逻辑写在 Oracle 过程/触发器里；C# 可以 **调用** 存储过程，但不能 **代替** 四类 Oracle 对象的考核要求。

## 四、Git 协作

**流程：** `main` ← PR ← `feature/xxx` ← 从 `main` 拉分支

**合并顺序：** B → C → D → E → F → G → H → I → J（按业务依赖；开发与合并可并行，合进 main 时按此顺序）

**易冲突文件（约定）：**

| 文件 | 约定 |
| --- | --- |
| `Application/Extensions/DependencyInjection.cs` | PR 中写清需注册项，由 A 合并时追加 |
| `Infrastructure/Extensions/DependencyInjection.cs` | 同上 |
| `frontend/src/router/index.ts` | 同上 |
| `Infrastructure/Data/AppDbContext.cs` | 不改（表已在 Oracle 建好） |
| `database/oracle/` | 只新增自己的 `.sql`，不覆盖他人 |

**PR 描述必填：** 完成的 API、页面、Oracle 对象、需 A 追加的 DI/路由。

**分工依据：** GitHub 提交记录、组内协作记录可作为答辩前分数占比依据。

## 五、个人开发步骤

对照 Member 样板（`MembersController`、`MemberRepository`、`LoginView` 等）：

```text
1. git pull origin main && git checkout -b feature/你的模块
2. 明确本模块用例（见第二节）
3. IXxxRepository → XxxRepository → DTO → AppService → Controller
4. 浏览器访问 http://localhost:5078/api/你的接口 验证 JSON
5. frontend/src/api/xxx.ts → views/XxxView.vue
6. 在 Oracle 执行第三节中的脚本并验证
7. dotnet build + npm run build 通过
8. push → PR → 搭档 Review → A 按顺序合并
```
